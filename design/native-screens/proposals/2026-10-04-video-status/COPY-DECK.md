## 0. Conventions

1. **Source strings are sentence case.** Mono caps rendering is a style. *Tag* strings render in mono
   caps; *Line* and *Helper* strings render as written.
2. **Numbers** are JetBrains Mono, tabular: `42%`, `8:12`, `2 angles`.
3. **Names:** initial + last name; possessive `{name}'s` (as `angleName()` today).
4. **No em dashes, no exclamation marks, no emoji.** Errors say what failed and what to do. The retry
   action is always **Try again**.
5. **Nothing blames or guesses about another person.** Another person's angle is described by what
   the server knows ("We haven't heard from {name}'s phone"), never by what they did or why. It is
   `attention` (amber) while it can still arrive and `ink-3` (grey) once it is final. Red never
   appears on another person's angle.
6. **Red only when the viewer can act.** `negative` + alert glyph + `Try again` appears only for the
   viewer's own upload, only on the phone that recorded it, and only when the clip file is on that
   phone. Anything the viewer cannot fix is grey (M3).
7. **Every non-terminal state says what happens next; every failure says what to do or that nothing
   is needed.**
8. **Color classes** (token names; the boards draw the dark values):
   | Class | Token (dark / light) | Used for |
   |---|---|---|
   | progress | `ink-2` #9CA3AF / #4B5563, 2px track `hairline-strong` | uploading |
   | waiting | `attention` #F59E0B / #92400E | waiting_for_phone, upload_paused, processing, waiting_for_angle, building, collecting (another person's angle, still recoverable) |
   | done | `ink` + check glyph | ready, uploaded |
   | act | `negative` #EC6A74 / #AC2B34 + alert glyph | MY upload failed or abandoned, on the recording phone, file present |
   | info | `ink-3` #8D929D / #575C68 | final states with nothing to do |
   Gain green is not used for any video state.
9. **One source of truth:** the match detail **Film status** plate. Every other surface is a digest of
   it and must obey the contradiction rules in section 9.
10. **Touch targets:** every new control is at least 44 px tall (M13).

Film Room badge priority (one badge + `2 ANGLES`; the {term} inside a badge renders uppercase like
the rest of it, m2): local `Didn't upload` > local `Upload paused` >
local uploading overlay > `Waiting {mm:ss}` > `Building {term}` > `Uploading` (collecting) > `New` >
`Breakdown ready` > `No film` > none. `Processing` is only ever an angle row, never a card badge
(B1.1).

**Contradiction rules (every device, every surface):**
1. Phase and other people's angles come only from the RPC. Only "Your angle" on the recording phone
   may be fresher (local job).
2. The same state uses the same string on every surface (the build keeps every string in one
   `video-status-copy.ts` keyed by relation, state and phase, with a lint test).
3. `{n}` in any phase line equals the number of rows that are Ready and in `angles_used` (B1.2).
4. Nothing offers playback of an angle that is not `ready` (B1.3): the verdict CTA reads `Open match`
   until at least one angle is ready, then `Watch film`; the match detail hero has no play button
   and no duration until the selected angle is ready; the angle switcher lists only ready angles
   (hidden under two).
5. The countdown is `wait_deadline_at` minus server time (`server_now` + time since fetch). At 0:00
   the client re-fetches; until the server moves on, the tag reads `Any second now`.
6. "Extended wait" copy shows only when the RPC says `wait_extended` = true.
7. "No film" shows only after the grace window (M11) or when `angles_expected` is known and settled.
8. Red appears only under 0.6.
9. The match detail hero shows the selected ready angle's duration, never the match clock (m4).

## 10. Accessibility (M14)

1. No live region on the plate, strip or rows. Announce with
   `AccessibilityInfo.announceForAccessibility` (iOS and Android) only when the **phase** changes or a
   **row's state** changes (not on percent or countdown ticks). Example: `D. Okafor's angle is
   ready to watch.`
2. Each row is one accessible element: label `{label}, {tag}, {helper}`; uploading rows use
   `accessibilityRole="progressbar"` with `accessibilityValue {min: 0, max: 100, now: pct}`.
3. Countdown: label `8 minutes 12 seconds left`; announced only at 5 min, 1 min and 0.
4. `Try again` buttons: label `Try again: upload match video`. Retry failure announces
   `Still can't upload. Check your connection.`
5. Strip: label `Uploading match video, 42 percent. Opens the match.`

## 12. Discard (coordinator default 2026-10-05; owner may override)

jits-n2im.5 asks for a way to drop a recording that can never upload. Discard exists only for a
**terminal** failure of the viewer's own upload, on the phone that recorded it, **while the clip
file is still on that phone** (clip over the limit, server rejected). It is never offered for a
retryable failure (that gets `Try again`), never when the clip is already gone (nothing to drop),
and never on another device. The state stays `info` (grey, deck 0.6): Discard is a quiet secondary
action, alone (a terminal state has no `Try again`), 44 px tall, never red.

| Element | Copy |

| Confirm title | `Discard this recording?` |
| Confirm body | `It can't be uploaded, and it will be deleted from this phone.` |

## 14. Build notes (jits-n2im.25; how the gates and gaps are resolved in code)

All strings live in `apps/mobile/lib/video/video-status-copy.ts`; `lib/video/film-status.ts`
derives the one view every surface renders.

1. **Multi-angle gate.** "Fusion live" means the status document carries any fusion field
   (`wait_extended` not null, `dispatched_at`, `angles_used`, `angles_used_count` or
   `late_angle_until`). Without it: the collecting helper for `{k}` >= 2 is the single-angle
   `Your {term} starts as soon as it's in.`, building reads `Building your {term}.` (never `from {n}
   angles`), and no after-dispatch, late-angle or "updated with" helper is shown.
2. **Timekeeper building, one angle or no fusion count:** `Building the players' {term}s.` (4b with
   the "from {n} angles" clause dropped, as 4a does for `{n}` = 1).
3. **Merge rule edge:** while this phone holds an upload job, `no_video_yet` and `nobody_recorded`
   render as collecting (`Your film is on its way.`), so the plate never says "No video yet" over
   "Your angle: Uploading".
4. **Not drawn yet:** `Upload now` (2a, waiting_for_phone with the clip found) and the "late angle in
   after you shared" plate helper (4a) have no server or client signal today; the strip's `Preparing
   upload` state is not shown (the store's `pending` entry also means "recording started").
5. **The timekeeper's match page** is the plate alone (`get_match_details` refuses the timekeeper;
   the status RPC admits them), titled with the two competitors' short names.
6. **Rule 4 reads PLAYABLE, not analysed (coordinator decision 2026-10-05).** An angle is watchable
   as soon as the playback query can open its bytes (the shipped `angleWatchable` rule: a
   normalized or original file, whether the angle is ready, sliced, analysing, analysed, or
   pipeline-failed with the file still there). Analysis never gates playback. This applies to the
   match detail hero, the plate's rows, the angle switcher and the verdict CTA (`Open match` until an
   angle is playable, then `Watch film`). Row tags keep the shipped distinctions:
   | Server state | Playable | Tag | Class |
   |---|---|---|---|
   | processing | yes | `Analyzing` | waiting (it plays: duration and chevron) |
   | processing | no (still merging) | `Processing` | waiting |
   | ready | yes | `Ready to watch` | done |
   | failed (pipeline) | yes | `Analysis failed · may still play` | info (grey, never red) |
   | failed (pipeline) | no file | `Not used` | info |
   | no_match | yes | `Not used` (with its helper) | info |
   The playable set comes from `get_match_details` (match detail and verdict). Where the status is
   read alone (the timekeeper's page, or before that read lands), only ready and no-match angles
   count as playable.
7. **Upload strip placement (coordinator decision 2026-10-05).** The strip is also hidden on the
   full-screen players (the match video player and the highlight viewer). On a pushed screen the
   strip pads the bottom safe area itself and the screen above it is given a bottom inset of 0, so
   the safe area is never padded twice.
